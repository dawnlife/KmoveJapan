# Q2. 객체 지향 프로그래밍에서 상속이 필요한 이유와 상속을 통해 얻을 수 있는 장점을 서술하시오.
## 1. 상속(Inheritance)이 필요한 이유
상속은 현실 세계의 논리적인 계층 구조를 소프트웨어에 그대로 반영하기 위해 필요합니다. 서로 다른 클래스들이 공통으로 가져야 하는 특징(상태와 기능)이 있다면, 이를 매번 중복해서 작성하는 대신 공통된 부모 클래스로 추상화하여 묶어내기 위해 상속이라는 구조를 사용합니다. 즉, 체계적이고 규격화된 객체의 확장을 위해 반드시 필요한 문법입니다.

## 2. 상속을 통해 얻을 수 있는 주요 장점
객체지향에서 상속을 올바르게(IS-A 관계가 명확할 때) 활용하면 다음과 같은 강력한 이점을 얻습니다.
- 코드 재사용성 극대화: 잘 만들어진 상위 클래스(부모)의 필드와 메서드를 하위 클래스(자식)가 그대로 물려받아(유산) 사용할 수 있습니다. 이로 인해 동일한 코드를 여러 번 작성하는 수고를 덜고 개발 생산성을 높일 수 있습니다.
- 유지보수성 향상: 시스템에 요구사항이 변경되거나 버그가 발생했을 때, 공통 로직이 들어있는 부모 클래스 단 한 곳만 수정하면 됩니다. 변경된 내용은 이를 상속받은 모든 자식 클래스에 자동으로 일괄 적용되므로 유지보수가 매우 효율적입니다.
- 다형성(Polymorphism) 구현의 기반: 상속은 객체지향의 꽃인 다형성을 구현하는 필수 전제 조건입니다. 부모 클래스 타입의 변수 하나로 다양한 자식 클래스의 객체들을 유연하게 다룰 수 있게 만들어 주어, 확장성 높은 시스템을 설계할 수 있게 합니다.

# Q3. 자바에서 다중 상속(Multiple Inheritance)을 지원하지 않는 이유와 이로 인해 발생할 수 있는 문제를 서술하시오.
## 1. 자바가 다중 상속을 지원하지 않는 이유
자바는 언어 설계 초기부터 시스템의 복잡성을 줄이고 예측 가능성을 높이기 위해 클래스의 다중 상속을 의도적으로 금지했습니다. 가장 결정적인 이유는 다이아몬드 문제(Diamond Problem)로 인한 모호성 때문입니다.

- 메서드 충돌과 모호성: 만약 하위 클래스가 두 개의 상위 클래스(A, B)를 동시에 상속받았는데, A와 B에 이름과 매개변수가 완전히 똑같은 메서드(예: printInfo())가 존재한다고 가정해 보겠습니다.

- 실행의 혼란: 하위 클래스 객체에서 해당 메서드를 호출할 때, 자바 가상 머신(JVM)은 A와 B 중 어떤 부모 클래스의 메서드를 실행해야 할지 판단할 수 없는 치명적인 모호성(Ambiguity)에 빠지게 됩니다.

- 구조적 복잡도 증가: 다중 상속을 허용하면 클래스 간의 관계가 거미줄처럼 복잡하게 얽히게 되어 부모 클래스의 작은 변경이 시스템 전체에 예측할 수 없는 버그를 유발합니다.

2. 단일 상속으로 인해 발생할 수 있는 문제점
이러한 이유로 자바나 C# 같은 대부분의 현대 언어는 클래스의 단일 상속(Single Inheritance)만 지원합니다. 시스템을 안전하게 지켜주지만, 설계 시 다음과 같은 딜레마를 겪게 됩니다.

- 설계의 제약: 논리적으로 여러 부모의 특징을 동시에 물려받아야 하는 복합적인 객체를 모델링할 때, 문법적 제약으로 인해 구조를 직관적으로 표현하기 어렵습니다.

- 소중한 '단일 상속권'의 낭비: 자바에서 부모 클래스는 단 하나만 가질 수 있습니다. 단순한 코드 재사용을 위해 이 소중한 상속권을 소모해버리면, 정작 나중에 도메인 모델링 상 정말로 상속받아야 할 중요한 부모 클래스가 생겼을 때 상속 구조를 적용할 수 없게 됩니다.

# Q4. 메서드 오버라이딩(Method Overriding)의 개념과 부모 클래스의 메서드를 자식 클래스에서 재정의할 때 반드시 지켜야 하는 조건에 대해 서술하시오.
## 1. 메서드 오버라이딩(Method Overriding)의 개념
메서드 오버라이딩은 상속 관계(IS-A 관계)에 있는 부모 클래스에 이미 정의된 메서드를, 자식 클래스에서 자신의 도메인 성격에 맞게 내부 구현 로직을 새롭게 재정의하여 사용하는 객체지향 기법입니다.

- 실무적 의미: 부모의 메서드 이름을 그대로 사용하면서 내부 알맹이(행동)만 교체하는 구조입니다. 이를 통해 외부에서는 부모 타입으로 메서드를 호출하더라도, 런타임에 실제 자식 객체의 재정의된 메서드가 실행되는 다형성을 실현할 수 있습니다.

- 어원 비유: Overriding의 'Ride'는 '올라타다', '지배하다'라는 뜻을 가집니다. 즉, 부모가 물려준 기존 메서드 위에 자식이 새로 만든 메서드를 "덮어써 버린다"고 이해하시면 가장 직관적입니다.

## 2. 오버라이딩 시 반드시 지켜야 하는 4가지 문법적 조건
자바 컴파일러는 다른 팀원이 코드를 읽을 때 혼란을 겪지 않고, 시스템이 안전하게 동작하도록 오버라이딩에 엄격한 규칙을 적용합니다. 하나라도 위반하면 컴파일 에러가 발생합니다.

- ① 메서드 시그니처의 완벽한 일치 (가장 기본)

  - 부모 메서드와 메서드 이름, 매개변수의 타입·개수·순서, 그리고 반환 타입(Return Type)이 완전히 일치해야 합니다. (단, 반환 타입의 경우 부모 메서드 반환 타입의 하위 클래스 타입으로 변경하는 것은 허용됩니다 - 공변 반환 타입).

- ② 접근 제한자는 부모보다 좁은 범위로 변경 불가

  - 자식 클래스에서 재정의하는 메서드의 접근 허용 범위는 부모 클래스의 메서드보다 같거나 넓어야 합니다.

  - 예: 부모 메서드가 protected라면 자식은 protected나 public으로만 오버라이딩할 수 있으며, default나 private으로 범위를 좁힐 수 없습니다.

- ③ 부모 메서드보다 더 넓은 범위의 예외(Exception) 선언 불가

  - 자식 메서드는 부모 메서드가 던지는 예외보다 더 명시적이거나 더 구체적인 예외(하위 예외)만 던질 수 있으며, 부모보다 더 포괄적이고 큰 예외(Exception 등)를 마음대로 던질 수 없습니다.

- ④ 부모의 static, final, private 메서드는 오버라이딩 불가

  - static 멤버는 객체가 아닌 클래스에 종속되므로 오버라이딩 대상이 아닙니다.

  - final 키워드가 붙은 메서드는 변경을 금지하겠다는 선언이므로 오버라이딩이 원천 차단됩니다.

  - private 메서드는 자식 클래스에서 애초에 접근조차 할 수 없기 때문에 오버라이딩할 수 없습니다.
 
```JAVA
// 최상위 부모 클래스
class DigitalDevice {
	void turnOn() {
		System.out.println("기기의 전원을 켭니다.");
	}
}// 외형적 특성을 정의한 가상 부모 클래스 1
class SmartPhone extends DigitalDevice {
	@Override
	void turnOn() {
	System.out.println("화면에 로고가 켜지며 전원이 들어옵니다.");
	}
}// 기능적 특성을 정의한 가상 부모 클래스 2
class SmartWatch extends DigitalDevice {
@Override
void turnOn() {
System.out.println("시계 화면에 불이 들어오며 전원이 들어옵니다.");
}
}
```

# Q1. 다음 소스 코드에서 자식 클래스가 부모 클래스의 생성자를 명시적으로 호출하고자 한다. 빈칸 (A)에 들어갈 올바른 키워드를 작성하시오.
## 정답: super
자식 클래스에서 부모 클래스의 생성자를 명시적으로 호출할 때 빈칸 (A)에 들어갈 올바른 키워드는 super 입니다. (코드 문맥에 따라 super(); 또는 super(매개변수); 형태로 사용됩니다.)

## 💡 super 키워드의 핵심 실무 개념
- 부모 객체의 선행 생성: 자식 객체를 메모리에 생성(new)할 때, 자바는 논리적으로 자식 객체 내부에 부모 객체를 먼저 생성해야만 부모의 필드와 메서드를 정상적으로 물려받아(상속) 사용할 수 있습니다.

- 생성자 호출 강제: 이를 위해 자식 클래스의 생성자 내부 가장 첫 줄에는 반드시 부모 클래스의 생성자를 호출하는 super() 구문이 실행되어야 합니다.

- 컴파일러의 자동 삽입: 만약 개발자가 코드에 명시적으로 적지 않더라도, 자바 컴파일러가 자식 생성자의 맨 첫 줄에 부모의 기본 생성자인 super();를 보이지 않게 자동으로 삽입해 줍니다.

- 명시적 호출이 필수인 경우: 만약 부모 클래스에 기본 생성자가 없고 '매개변수가 있는 생성자'만 존재한다면, 컴파일러가 자동으로 super();를 넣었을 때 매칭되는 부모 생성자가 없어 컴파일 에러가 발생합니다. 이때 개발자가 직접 빈칸 (A)처럼 알맞은 값을 넣은 super(값);을 명시적으로 작성하여 에러를 방지해야 합니다.

# Q2. 자바에서 특정 클래스가 더 이상 다른 클래스의 부모가 되지 못하도록 상속을 금지하거나, 메서드가 오버라이딩되지 못하도록 차단할 때 사용하는 키워드를 빈칸 (A)에 작성하시오.
## 정답: final
## 💡 final 키워드의 핵심 실무 개념
자바에서 final은 "마지막의", "더 이상 변경될 수 없는"이라는 의미를 가지며, 선언되는 위치에 따라 아키텍처를 안전하게 보호하는 강력한 제약 조건으로 작동합니다.

- final 클래스 (상속 금지):

  - 클래스 선언부에 final을 붙이면 더 이상 자식 클래스를 가질 수 없는 최종(종단) 클래스가 됩니다.

  - 대표적인 예로 자바의 String이나 Math 클래스가 있습니다. 보안상 혹은 설계상 내부 로직이 완벽하게 검증되어 있어, 다른 개발자가 상속을 통해 임의로 기능을 변형하거나 훼손하는 것을 원천적으로 차단할 때 사용합니다.

- final 메서드 (오버라이딩 차단):

- 메서드 선언부에 final을 붙이면, 자식 클래스에서 이 메서드를 재정의(Overriding)할 수 없습니다.

  - 부모 클래스가 물려준 핵심 비즈니스 로직이나 보안상 절대 바뀌면 안 되는 알고리즘을 자식 클래스가 임의로 덮어쓰는(수정하는) 것을 막기 위해 사용합니다.

# Q3. 다음 요구사항에 맞게 Employee 클래스를 상속받는 Manager 클래스의 완전한 소스 코드를 작성하시오.
[요구사항]
Employee 클래스는 변경하지 않는다.
Manager 클래스는 Employee 클래스를 상속받는다.
Manager 클래스에 정수형 필드 bonus를 추가한다.
getDetails() 메서드를 오버라이딩하여 부모의 결과값 뒤에 ", 보너스: [bonus값]"을 연결하여 반환하도록 구현한다
```JAVA
class Employee{
    String name;
    int salary;

    Employee(String name, int salary) {
        this.name = name;
        this.salary = salary;
    }

    String getDetails(){
        return "이름: " + name + ", 급여: " + salary;
    }
}
```
## 정답
```JAVA
class Manager extends Employee {
    // 1. Manager 클래스에 정수형 필드 bonus 추가
    int bonus;

    // 2. 생성자 구현 (부모 클래스의 생성자 호출 필수)
    Manager(String name, int salary, int bonus) {
        super(name, salary); // 자식 생성자의 맨 첫 줄에서 부모 생성자를 명시적으로 호출
        this.bonus = bonus;  // 자신의 필드 초기화
    }

    // 3. getDetails() 메서드 오버라이딩
    @Override
    String getDetails() {
        // 부모의 getDetails() 결과를 가져온 뒤 보너스 문자열을 연결하여 반환
        return super.getDetails() + ", 보너스: " + bonus;
    }
}
```
# Q4. 다음 소스 코드의 실행 결과로 콘솔에 출력되는 내용을 순서대로 작성하시오.
```JAVA
class Parent{
    Parent() {
        System.out.println("Parent Constructor");
    }
}

class Child extends Parent{
    Child() {
        System.out.println("Child Constructor");
    }
}

public class Test{
    public static void main(String[] args){
        Child c = new Child();
    }
}
```
## 정답:
Parent Constructor
Child Constructor

## 🧐 왜 이런 순서로 출력될까요? (실행 흐름 분석)
자바의 상속 구조에서 객체가 생성되는 원리(앞서 다루었던 super 키워드)와 밀접한 관련이 있습니다.

1. 자식 객체 생성 호출: main 메서드에서 new Child();가 실행되며 Child 클래스의 생성자가 호출됩니다.

2. 부모 생성자의 선행 호출 (핵심): 자식 클래스의 생성자 내부 첫 줄에는 컴파일러에 의해 보이지 않는 super(); 가 자동으로 삽입되어 실행됩니다. 부모의 기능과 상태를 온전히 물려받기 위해 논리적으로 부모 객체를 먼저 메모리에 생성해야 하기 때문입니다.

3. Parent 생성자 실행: super(); 호출로 인해 Parent 클래스의 기본 생성자가 먼저 실행되어 "Parent Constructor"가 출력됩니다.

4. Child 생성자 실행 완료: 부모 객체의 생성이 끝난 후, 다시 Child 클래스 생성자의 나머지 코드가 마저 실행되어 "Child Constructor"가 출력됩니다.


# Q5. 다형성을 활용하여 부모 타입의 참조변수로 자식 객체를 참조할 때, 자식 클래스에서 새롭게 추가한 메서드를 호출하기 위해 필요한 다운캐스팅(Downcasting) 코드를 작성하려고 한다. 빈칸 (A)에 들어갈 올바른 소스 코드를 작성하시오.
```JAVA
class Animal{
    void breathe(){
        System.out.println("숨을 쉽니다.");
    }
}

class Dog extends Animal{
    void bark(){
        System.out.println("멍멍 짖습니다.");
    }
}

public class Main{
    public static void main(String[] args){
        Animal myAnimal = new Dog(); // 업캐스팅
        myAnimal.breathe();

        // bark()를 호출하기 위한 다운캐스팅 진행
        (A)
        myDog.bark();
    }
}
```
## 정답: Dog myDog = (Dog) myAnimal;
## 🧐 다운캐스팅(Downcasting)이 필요한 이유
- 타입의 한계: Animal myAnimal = new Dog(); 와 같이 업캐스팅(Upcasting)된 상태에서, myAnimal 변수는 태생이 Animal 타입(부모)입니다. 따라서 실제 메모리에 생성된 알맹이가 Dog 객체라 할지라도, 자바 컴파일러는 부모 클래스에 정의된 breathe() 메서드까지만 접근을 허용합니다.

- 명시적 형변환: 자식 클래스인 Dog에만 새롭게 추가된 bark() 메서드를 호출하기 위해서는, 컴파일러에게 "이 객체의 실제 알맹이는 Dog니까 Dog 리모컨으로 바꿔줘"라고 명시적으로 알려주어야 합니다. 이때 클래스 타입 앞에 (Dog)라는 캐스팅 연산자를 붙여 강제로 타입을 변환하는 것을 다운캐스팅이라고 합니다.
