# 구조체 스타일 vs 일반 클래스 비교

## 핵심 차이 비교표

| 항목 | 구조체 스타일 | 일반 클래스 |
|------|-------------|-----------|
| 필드 접근 | `s1.score = 85` | 생성자/메서드 통해서만 |
| 출력 위치 | main에서 직접 | `printInfo()` 메서드 |
| 잘못된 값 | 차단 불가 | 생성자에서 차단 |
| 기능 추가 | main이 길어짐 | 클래스에 메서드 추가 |
| 유지보수 | 어려움 | 클래스만 수정하면 됨 |

---

## 한 줄 정리

> **구조체** = 데이터 보관함 (그릇만 있음)  
> **일반 클래스** = 데이터 + 스스로 판단하고 행동하는 객체

Java에서 구조체가 없는 이유 — 클래스가 구조체 역할을 포함해서 그 이상을 할 수 있기 때문.

7\. 필드는 객체가 가지는 데이터(상태), 메서드는 객체가 할 수 있는 행동(기능). 필드는 명사, 메서드는 동사로 이해하면 쉬움. 둘이 합쳐져야 완전한 객체가 됨.



8\. 생성자는 객체가 new로 생성될 때 자동으로 호출되는 특수 메서드. 필드 초기화가 주 역할이며, 클래스 이름과 동일하고 반환타입이 없는 게 핵심 특징. 생성자 없으면 Java가 기본 생성자를 자동으로 만들어줌.



9\. 접근 제한자는 필드·메서드·클래스에 대한 외부 접근 범위를 제어하는 키워드. public > protected > default > private 순으로 범위가 좁아짐. 실무에서 필드는 무조건 private, 외부 공개 메서드는 public이 기본 규칙.
