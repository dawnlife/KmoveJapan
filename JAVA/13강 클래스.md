## Q1. 데이터와 함수의 결합 측면에서 클래스가 구조체보다 유리한 이유는 무엇인가?
구조체는 단순히 '데이터(상태)'만 묶어두는 바구니에 불과합니다. 
반면, 클래스는 데이터(필드)와 그 데이터를 조작하는 함수(메서드)를 하나의 캡슐(Capsule)로 결합합니다. 
이를 통해 내부 데이터를 외부의 무분별한 접근으로부터 보호하고, 유효성 검사를 거친 메서드를 통해서만 조작하도록 강제하여 데이터 무결성을 유지할 수 있습니다. 

구조체는 데이터 묶음, 클래스는 데이터 + 동작(메서드)까지 포함. Java엔 struct가 없고 클래스만 존재. 개념적 차이를 알면 객체지향 설계 이해가 훨씬 빨라짐.

## Q2. 구조체형 클래스와 일반 클래스 소스 비교
### 구조체 스타일 vs 일반 클래스 비교

#### 핵심 차이 비교표

| 항목 | 구조체 스타일 | 일반 클래스 |
|------|-------------|-----------|
| 필드 접근 | `s1.score = 85` | 생성자/메서드 통해서만 |
| 출력 위치 | main에서 직접 | `printInfo()` 메서드 |
| 잘못된 값 | 차단 불가 | 생성자에서 차단 |
| 기능 추가 | main이 길어짐 | 클래스에 메서드 추가 |
| 유지보수 | 어려움 | 클래스만 수정하면 됨 |

---
```JAVA
// 1. 구조체형 클래스 (안티 패턴: 캡슐화 위반)
class StudentStruct {
    public String name;
    public int score; // 외부에서 누구나 직접 접근해 값을 조작할 수 있음 [cite: 4]
}

// 2. 일반 클래스 (객체지향형: 캡슐화 적용)
class Student {
    private String name;
    private int score; // private으로 필드를 닫아 직접 접근 차단 

    public Student(String name, int score) {
        this.name = name;
        this.score = score;
    }

    public void printInfo() {
        System.out.println(this.name + "의 점수는 " + this.score + "점 입니다.");
    }
}
```

## 한 줄 정리

> **구조체** = 데이터 보관함 (그릇만 있음)  
> **일반 클래스** = 데이터 + 스스로 판단하고 행동하는 객체

Java에서 구조체가 없는 이유 — 클래스가 구조체 역할을 포함해서 그 이상을 할 수 있기 때문.


## Q3. 절차지향 vs 객체지향의 대표 언어 및 차이점

- 대표 언어: 절차지향(C), 객체지향(Java, C++, C#)

- 차이점: 절차지향은 "어떤 순서로 로직을 실행할 것인가(함수 중심)"에 초점을 맞춥니다. 반면, 객체지향은 "어떤 객체들이 모여서 서로 어떻게 협력할 것인가(데이터와 책임 중심)"에 초점을 맞춥니다.
  

캡슐화 — 데이터 숨기기 (private)

상속 — 부모 클래스 기능 물려받기

다형성 — 같은 메서드, 다른 동작

추상화 — 핵심만 뽑아서 설계



## Q4. 유지보수와 코드 재사용성 측면에서 객체지향이 유리한 이유

객체지향은 시스템을 독립적인 책임을 가진 '객체' 단위로 분할합니다. 향후 요구사항이 변경되거나 버그가 발생했을 때 시스템 전체를 뒤지지 않고 해당 객체만 수정하면 되므로 결합도가 낮아져 유지보수가 쉽습니다. 또한, 잘 만들어진 객체는 상속이나 합성(Composition)을 통해 다른 프로젝트에서도 부품처럼 쉽게 재사용할 수 있습니다.

기능 하나 수정	관련 함수 전부 찾아서 수정	해당 클래스만 수정

비슷한 기능 추가	비슷한 코드 복붙	상속으로

재사용	팀 협업함수 충돌 잦음	클래스 단위로 역할

분리규모 	커질수록유지보수 비용 급증	구조 유지 가능



객체지향은 코드를 역할별로 분리해서 수정할 때 해당 객체만 건드리면 됨. 상속·인터페이스로 기존 코드를 그대로 재사용 가능. 절차지향은 코드 하나 바꾸면 연결된 전체를 다 확인해야 해서 규모 커질수록 불리함.



## Q5. 절차지향 vs 객체지향 작성 예시 (자동차 드라이브)

```JAVA
// [절차지향 방식] 데이터와 함수가 분리됨
class CarData {
    public String model = "BU";
    public int fuel = 100;
}
class CarProcedure {
    // 함수가 외부에서 데이터를 받아 조작
    public static void drive(CarData car) {
        car.fuel -= 10;
        System.out.println(car.model + " 주행 완료. 남은 연료: " + car.fuel);
    }
}

// [객체지향 방식] 자신의 데이터는 자신이 관리함
class CarObject {
    private String model = "BU";
    private int fuel = 100;

    // 스스로 자신의 상태(연료)를 체크하고 조작
    public void drive() {
        this.fuel -= 10;
        System.out.println(this.model + " 주행 완료. 남은 연료: " + this.fuel);
    }
}
```

## Q7. 필드(Field)와 메소드(Method)의 역할
- 필드: 객체의 상태(데이터)를 저장합니다.

- 메소드: 객체의 동작(기능)을 정의하고, 내부 상태를 변경하거나 외부와 소통하는 역할을 합니다.

필드는 객체가 가지는 데이터(상태), 메서드는 객체가 할 수 있는 행동(기능). 
필드는 명사, 메서드는 동사로 이해하면 쉬움. 둘이 합쳐져야 완전한 객체가 됨.



## Q8. 생성자(Constructor)의 특징과 역할
특징은 클래스 이름과 완전히 동일하며 반환 타입이 없다는 것입니다. 
역할은 객체가 메모리에 생성(new)되는 순간 가장 먼저 호출되어, 
객체의 필수적인 필드들을 유효한 값으로 초기화하여 불완전한 상태의 객체가 돌아다니지 않도록 막는 것입니다.

생성자는 객체가 new로 생성될 때 자동으로 호출되는 특수 메서드. 필드 초기화가 주 역할이며, 클래스 이름과 동일하고 반환타입이 없는 게 핵심 특징. 생성자 없으면 Java가 기본 생성자를 자동으로 만들어줌.



## Q9. 자바의 접근 제한자(Access Modifier) 4가지

1. private: 해당 클래스 내부에서만 접근 가능. (캡슐화와 정보 은닉의 핵심) 

2. default (package-private): 동일한 패키지 내에서만 접근 가능. (아무것도 적지 않았을 때의 기본값)

3. protected: 동일 패키지 + 다른 패키지에 있더라도 상속받은 자식 클래스에서는 접근 가능.

4. public: 외부의 모든 클래스에서 제한 없이 접근 가능. (필드에 남용하면 데이터 무결성이 훼손됩니다.)

접근 제한자는 필드·메서드·클래스에 대한 외부 접근 범위를 제어하는 키워드. 
public > protected > default > private 순으로 범위가 좁아짐. 실무에서 필드는 무조건 private, 외부 공개 메서드는 public이 기본 규칙.

## Q11. static 멤버와 일반 멤버의 차이

- static 멤버: 클래스가 로딩될 때 메모리에 단 한 번 할당되며, 모든 객체가 값을 공유합니다. 객체를 생성(new)하지 않고도 클래스명.멤버로 접근할 수 있습니다.

- 일반 멤버: 객체가 new로 생성될 때마다 메모리에 개별적으로 생성되며 공유되지 않습니다.

static 멤버는 객체 생성 없이 클래스 자체에 소속, 일반 멤버는 객체에 소속.
static은 모든 객체가 공유하는 공용 데이터·메서드에 사용. 메모리 올라가는 시점도 다르고 this 사용 여부도 다름.

## Q13. 필드와 지역변수의 차이

- 필드: 클래스 블록 내에 선언되며, 객체가 존재하는 동안 유지됩니다. 초기화하지 않아도 타입에 맞는 기본값(0, null 등)이 자동으로 들어갑니다.

- 지역변수: 메서드(또는 생성자) 블록 내에 선언되며, 해당 블록이 종료되면 메모리에서 즉시 소멸합니다. 사용하기 전에 반드시 수동으로 초기화해야 합니다.

필드는 클래스 안 메서드 밖에 선언되고 객체 전체에서 사용, 지역변수는 메서드 안에 선언되고 그 메서드 안에서만 사용.
필드는 기본값 자동 초기화, 지역변수는 직접 초기화 안 하면 에러. 메모리 저장 위치도 다름.

--------
```JAVA
class SmartPhone {
    // 1. static 필드 (클래스 멤버)
    public static String manufacturer = "GlobalTech";
    // 2. 인스턴스 필드 (캡슐화 적용)
    private String model;
    private int batteryLevel;
    // 3. 생성자 (this 키워드 사용)
    public SmartPhone(String model, int batteryLevel) {
        this.model = model;
        this.batteryLevel = batteryLevel;
    }
    // 4. 인스턴스 메소드
    public void useApp(String appName) {
        this.batteryLevel -= 5;
        System.out.println(this.model + "에서 " + appName + " 실행. 남은 배터리: " + this.batteryLevel);
    }
    // 5. static 메소드
    public static void printCompany() {
        System.out.println("제조사: " + manufacturer);
    }
}
```
```JAVA
public class Main {
    public static void main(String[] args) {
        // 1. 객체 생성 (인스턴스화)
        SmartPhone myPhone = new SmartPhone("Galaxy S26", 100);
        SmartPhone yourPhone = new SmartPhone("iPhone 17", 90);

        // 2. 인스턴스 메소드 호출
        myPhone.useApp("YouTube");
        yourPhone.useApp("Instagram");

        // 3. static 멤버 호출 (객체 생성 없이 클래스 이름으로 접근)
        SmartPhone.printCompany();
        System.out.println("기본 제조사: " + SmartPhone.manufacturer);
    }
}
```

## Q5. 접근 제한자란? private 제한자의 정보 은닉 측면에서의 중요성

클래스 외부에서 내부 멤버로 접근할 수 있는 권한을 통제하는 문법입니다. `model`과 `batteryLevel`을 `private`으로 숨기면, 
`main` 메서드 등 외부에서 `myPhone.batteryLevel = -500;`과 같이 비정상적인 값을 마음대로 주입하는 것을 원천적으로 차단하여 시스템의 안전성을 지킬 수 있습니다.

- 접근 제한자 = 외부에서 클래스 멤버에 접근할 수 있는 범위를 제어하는 키워드.

- 직접 접근을 막으면 잘못된 값 입력 차단, 데이터 무결성 보장 가능. 이게 캡슐화의 실제 효과.



## Q6. 객체 생성(인스턴스화)과 저장 위치

설계도(클래스)를 바탕으로 메모리상에 실제 동작 가능한 실체를 만들어내는 과정입니다. 
`new` 연산자를 통해 생성된 실제 데이터(객체)는 메모리의 **힙(Heap)** 영역에 저장됩니다.

- 인스턴스화 = 클래스(설계도)를 기반으로 new 키워드를 통해 실제 객체를 메모리에 생성하는 것.


## Q7. this 키워드를 활용한 필드/매개변수 구분 예시

생성자 내부의 `this.model = model;` 구문에서, 점(.) 앞의 `this`는 객체 자신을 가리킵니다. 
따라서 좌항 `this.model`은 클래스에 선언된 인스턴스 필드를 의미하고, 
우항 `model`은 외부에서 전달받은 생성자의 매개변수(지역변수)를 의미하여 명확하게 구분이 가능해집니다.

- this가 "지금 이 메서드를 호출한 바로 그 객체" 를 명확히 가리키는 것.


## Q8. static(클래스 멤버)과 인스턴스 멤버의 근본적 차이

메모리 할당 시점과 공유 여부입니다. 
static 멤버는 프로그램이 시작될 때 한 번만 만들어져 모든 객체가 하나를 공유하지만, 
인스턴스 멤버는 `new` 키워드로 객체를 생성할 때마다 메모리에 매번 새롭게(독립적으로) 복제되어 만들어집니다.

||static 멤버|인스턴스 멤버|
|-|-|-|
|소속|클래스|객체|
|메모리 생성|클래스 로딩 시|new 실행 시|
|공유 여부|모든 객체 공유|객체마다 독립|
|접근 방법|SmartPhone.manufacturer|myPhone.model|


## Q9. SmartPhone.printCompany() 호출이 가능한 이유

`printCompany()` 메서드에 `static` 키워드가 붙어 있기 때문입니다. 
이는 특정 객체의 인스턴스 상태에 의존하지 않으므로, 
객체를 굳이 메모리에 올리지(`new`) 않아도 클래스 이름만으로 메서드 영역(Method Area)에 접근하여 직접 호출할 수 있습니다.

- printCompany()에 static 키워드가 붙어있기 때문.

- static 메서드는 클래스가 로딩되는 순간 메모리에 올라가기 때문에 myPhone, yourPhone 같은 객체가 없어도 이미 존재함.


## Q10. "Galaxy S26"이 객체 필드에 저장되는 과정 (this 연관)

1. `new SmartPhone("Galaxy S26", 100)`을 호출하면, 힙(Heap) 메모리에 새로운 스마트폰 객체가 생성됩니다.

2. 생성자의 지역변수(매개변수)인 `model`에 "Galaxy S26"이라는 문자열이 잠시 담깁니다.

3. `this.model = model;` 라인이 실행되면서, 새롭게 생성된 바로 그 객체(this)의 내부 필드 영역(`this.model`)에 "Galaxy S26"이라는 값이 최종적으로 복사되어 영구적으로 상태가 저장됩니다.
