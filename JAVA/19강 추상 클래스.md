## Q1. 추상클래스(Abstract Class)의 정의와 왜 인스턴스(객체)를 직접 생성할 수 없는지 그 이유를 설명하시오.
### 1. 추상 클래스(Abstract Class)의 정의
- 추상 클래스는 내부의 구현 로직이 완성되지 않은 '미완성된 설계도'입니다. 일반적으로 구현부 { }가 없는 추상 메서드(Abstract Method)를 하나 이상 포함하고 있으며, 클래스 선언부에 abstract 키워드를 붙여 정의합니다.

- 핵심 역할: 자식 클래스들이 공통으로 가져야 할 상태(필드)와 기능(메서드)을 물려주면서도, 특정 기능은 자식 클래스의 도메인에 맞게 반드시 직접 구현(오버라이딩)하도록 컴파일러 차원에서 강제하는 뼈대 역할을 합니다.

### 2. 인스턴스(객체)를 직접 생성할 수 없는 이유
추상 클래스는 new 키워드를 사용하여 메모리에 직접 인스턴스(객체)를 생성할 수 없도록 컴파일러에 의해 엄격하게 막혀 있습니다. 그 이유는 다음과 같습니다.

- 불완전한 로직 호출 방지 (기술적 이유): 추상 클래스 안에는 실행할 알맹이(구현부)가 없는 추상 메서드가 존재할 수 있습니다. 만약 객체 생성을 허용한다면, 개발자가 이 빈껍데기 메서드를 호출했을 때 시스템은 무엇을 실행해야 할지 몰라 치명적인 오류에 빠지게 됩니다.

- 의미 없는 객체 생성 차단 (설계적 이유): 다형성을 활용할 때 부모 클래스는 자식들을 묶어주는 '리모컨'이나 '공통 틀' 역할만 수행해야 하는 경우가 많습니다. 만약 누군가 실수로 부모 객체를 직접 생성해버리면, 실행되지도 않거나 의미 없는 기본 껍데기 로직이 실행되는 버그가 발생할 수 있습니다.

- 안전한 아키텍처 유도: 부모 클래스를 설계할 때 억지로 껍데기 구현부를 만들지 않고 추상 클래스로 선언하면, 객체의 직접 생성을 막아 시스템의 예측 가능성을 높일 수 있습니다.

## Q2. 추상 메서드(Abstract Method)란 무엇이며, 이를 포함한 클래스를 상속받는 자식 클래스가 반드시 지켜야 하는 문법적 규칙을 서술하시오.
### 1. 추상 메서드(Abstract Method)의 정의
추상 메서드는 내부에 실행할 알맹이인 구현부 { }가 없는 미완성 메서드입니다.

- 메서드의 선언부만 존재하며, 반환 타입 앞에 abstract 키워드를 붙여 정의합니다.

- "이 클래스를 상속받는 객체라면 반드시 이러한 기능(행동)을 가지고 있어야 한다"는 역할의 명세(껍데기)만을 선언해 두는 것입니다.

### 2. 자식 클래스가 반드시 지켜야 하는 문법적 규칙
추상 메서드를 하나라도 포함한 추상 클래스를 상속(extends)받는 자식 클래스는 다음의 엄격한 문법적 규칙을 따릅니다.

- 필수 오버라이딩(Overriding) 강제: 자식 클래스는 부모로부터 물려받은 추상 메서드의 빈 구현부 { }를 자신의 도메인 성격에 맞게 반드시 직접 구현(오버라이딩)해야 합니다.

- 컴파일러의 강력한 통제: 만약 자식 클래스가 이 필수 비즈니스 로직을 오버라이딩하지 않고 누락한다면, 자바 컴파일러는 즉시 에러를 발생시켜 프로그램 실행 자체를 막아버립니다.

- (참고) 만약 자식 클래스에서도 당장 구현할 수 없다면, 자식 클래스 본인조차도 abstract 클래스로 선언하여 책임을 다음 세대로 미뤄야만 컴파일 에러를 피할 수 있습니다.

## Q3. 일반 클래스와 추상클래스의 차이점을 생성자, 멤버 변수, 메서드 구현 관점에서 비교하여 설명하시오.

### 1. 일반 클래스 vs 추상 클래스 핵심 비교
|구분|일반 클래스 (Regular Class)|추상 클래스 (Abstract Class)|
|--|--|--|
|인스턴스(객체) 생성|new 연산자로 직접 생성 가능|new 연산자로 직접 생성 불가|
|생성자 (Constructor)|직접 객체를 메모리에 올릴 때 사용|자식 객체가 생성될 때 super()를 통해 호출됨|
|멤버 변수 (Field)|"인스턴스 변수, 정적(static) 변수 모두 가짐"|일반 클래스와 완전히 동일함 (상태 소유 가능)|
|메서드 (Method)|모든 메서드의 구현부 { }가 완성되어야 함|완성된 메서드와 미완성(추상) 메서드 혼합 가능구분|일반 클래스 (Regular Class)|추상 클래스 (Abstract Class)|
|인스턴스(객체) 생성|new 연산자로 직접 생성 가능|new 연산자로 직접 생성 불가|
|생성자 (Constructor)|직접 객체를 메모리에 올릴 때 사용|자식 객체가 생성될 때 super()를 통해 호출됨|
|멤버 변수 (Field)|"인스턴스 변수| 정적(static) 변수 모두 가짐"|일반 클래스와 완전히 동일함 (상태 소유 가능)|
|메서드 (Method)|모든 메서드의 구현부 { }가 완성되어야 함|완성된 메서드와 미완성(추상) 메서드 혼합 가능|

### 2. 관점별 상세 차이점 및 오해 바로잡기
#### 1) 생성자 (Constructor) 관점
초보 개발자들이 가장 많이 오해하는 부분이 "추상 클래스는 객체를 만들 수 없으니 생성자도 없겠지?"라는 착각입니다. 추상 클래스도 반드시 생성자를 가집니다.

- 일반 클래스: 자신이 직접 메모리에 인스턴스화될 때 필드 값을 초기화하기 위해 생성자가 호출됩니다.

- 추상 클래스: 직접 new를 할 수는 없지만, 자식 클래스가 객체로 생성될 때 내부적으로 부모(추상 클래스)의 생성자가 먼저 호출되어(super()) 물려줄 필드들을 초기화합니다.

#### 2) 멤버 변수 (Member Variable) 관점
이 부분은 두 클래스 간에 차이가 없습니다.

- 일반 클래스와 추상 클래스 모두 객체의 상태를 나타내는 인스턴스 변수(필드)를 가질 수 있으며, 접근 제한자(private, protected 등)도 자유롭게 사용할 수 있습니다.

- (참고) 상태(필드)를 가질 수 있다는 이 점이, 원칙적으로 상수를 제외한 변수를 가질 수 없는 '인터페이스(Interface)'와 추상 클래스를 구분 짓는 가장 결정적인 차이입니다.

#### 3) 메서드 구현 (Method Implementation) 관점
- 일반 클래스: 설계도 안에 있는 모든 기능은 실행 가능한 알맹이(구현부 { })를 완벽하게 갖추고 있어야 합니다.

- 추상 클래스: 공통으로 쓸 완성된 일반 메서드도 가질 수 있지만, 자식 도메인마다 다르게 구현해야 하는 기능은 구현부 없이 껍데기만 있는 abstract 메서드로 남겨둘 수 있습니다.


## Q4. 다형성(Polymorphism) 관점에서 추상클래스를 부모 타입으로 선언하여 사용하는 이유와 이점을 설명하시오.
### 1. 다형성 관점에서 추상 클래스를 부모 타입으로 사용하는 이유
다형성의 핵심은 "부모 타입의 참조 변수(리모컨) 하나로 다양한 자식 객체들을 제어하는 것"입니다. 이때 부모 클래스를 추상 클래스로 선언하면 다음과 같은 구조적 이점을 얻습니다.

- 안전한 규약(Contract) 보장: 추상 클래스의 '추상 메서드'는 자식 클래스가 반드시 해당 메서드를 구현(오버라이딩)하도록 컴파일러가 강제합니다. 따라서 부모 타입의 변수로 해당 메서드를 호출했을 때, 구현체가 없어 에러가 발생할 위험이 0%로 보장됩니다.

- 의미 없는 객체 생성 차단: 다형성을 위해 묶어두는 부모 개념(예: Animal, Payment)은 그 자체로 실체가 없는 추상적인 개념일 때가 많습니다. 이를 추상 클래스로 선언하면, 누군가 실수로 new Animal()처럼 의미 없는 껍데기 객체를 생성하여 발생할 수 있는 런타임 버그를 원천적으로 막아줍니다.

### 2. 추상 클래스 타입 선언을 통해 얻는 실무적 이점
|구분|주요 이점 및 설명|
|--|--|
|유연한 그룹화 (업캐스팅)|"서로 다른 자식 객체(신용카드, 카카오페이 등)들을 Payment라는 하나의 추상 부모 타입 배열이나 리스트로 묶어서 일괄 처리할 수 있습니다."|
|동적 바인딩의 안전성|"부모 리모컨의 추상 메서드 버튼을 누르면, 런타임 환경에서는 실제 메모리에 있는 자식 객체의 덮어씌워진(오버라이딩된) 로직이 무조건 안전하게 우선 실행됩니다."|
|OCP (개방-폐쇄 원칙) 준수|"시스템에 새로운 자식 클래스(예: 네이버페이)가 추가되더라도, 부모 타입으로 제어하고 있는 핵심 비즈니스 로직(for문 등)은 단 한 줄도 수정할 필요가 없습니다."|
